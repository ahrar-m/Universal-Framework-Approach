Methodology — Universal Framework Approach

Every metric you care about — monthly profit, process efficiency, a product-design score — is a single main equation assembled from small blocks. Blocks plug into one another, wires carry values between them, and one green Result block gives you the final number. This page explains how that works and walks you through building a real model from scratch.

The idea

A spreadsheet hides its reasoning inside formulas that are invisible until you click a cell. The Universal Framework Approach makes the reasoning the artefact: a metric is one equation, and the equation is built visually out of small blocks. A Value input holds a named number. An Operation or Formula combines values. Wires carry values from one block to the next. A Result block presents the final number.

This beats a spreadsheet for four practical reasons:

  • The shape of the reasoning is visible. You can see the structure of the model at a glance, hand it to a colleague, and argue about the structure rather than about cell references.
  • Every intermediate value is exposed. Revenue, variable cost and total cost are real blocks with real numbers on them — not side calculations in columns F through K.
  • Units are checked. The engine knows what kind of quantity each number is, so a total mistakenly used as a per-unit rate is caught instead of quietly producing nonsense.
  • You can see which input actually drives the outcome. The sensitivity panel ranks your inputs by how much they move the result.

The four block types

Value input

A named number with a unit

A Value input is a named number with a unit and an optional Min / Likely / Max range. It is named because formulas refer to inputs by name, not by position.

Example: price — value 49, unit $/unit, min 39, likely 49, max 59.

Operation

Two ports or twenty, one calculation

An Operation performs exactly one of: Add, Subtract, Multiply, Divide, Power, Minimum, Maximum, Round, Percent of, and the result is shown directly on the block. Subtract, Divide, Power, Round and Percent of have two input ports, a and b. Add, Multiply, Minimum and Maximum take as many inputs as you like: press + add input on the block (or Add input in Block settings) to grow the list, and every input is folded into the one result. Empty ports are ignored, a single connected input passes straight through, and every term is checked to be the same kind of quantity.

Example: a Multiply block with a = price (49) and b = volume (1,200) shows 58,800.

Formula

A typed expression over named inputs

A Formula holds one typed expression over named inputs, for example price * volume * (1 - churn). The block's inputs are the named ports you add to it — anything the expression references must be one of those inputs.

Example: a Formula block with inputs price, volume and churn can use those three names and nothing else.

Result

The final outcome of the model

The Result block is the outcome of the model, with an optional Display unit that presents it the way you want.

Example: Title Monthly profit, Display unit $, showing $27,700.

How values flow

Wires connect an output port to an input port. The model is a directed acyclic graph: values travel one way, from inputs to the result. There is no back-flow and no hidden state.

  • Loops are refused. If wiring a connection would create a cycle, the tool rejects it. A model is a computation, not a feedback simulation.
  • Each block shows its current value. Change an input and every downstream block updates immediately.
  • Each wire shows what it carries. You can follow a number from the input that produced it, through every intermediate step, to the result.

Wiring without the fiddling

Connecting two blocks should not take three attempts. Three shortcuts make a link hard to miss, plus one that undoes one:

  • Wires magnetise to ports. Drag from a port towards the next block — well before you reach it, the wire snaps to the nearest port it is allowed to reach and lights it up. Release anywhere in that area and the link is made.
  • Drop the wire on the card itself. Let go anywhere on a block and the wire lands on that block's first free input — or on its output when you drag from an input. On an Add or Multiply block whose inputs are all filled, a fresh input is grown for the wire.
  • Tap, then tap. On touch: tap the output port, then tap the destination card or its port. While you decide, every port that can accept the link glows; tapping the same port again abandons the link.
  • Removing a wire. Tap the wire — it lights up and a small bar names the link — then tap Delete wire. This is the phone-friendly path, where there is no Delete key to press. You can also open the destination block's settings and tap the × beside the input to drop just that wire, or press Delete on a keyboard.

Keeping large models readable

  • Arrange lays the blocks out in flow order: value inputs on the left, the result on the right, and columns ordered so wires stay short and crossings few. You can still drag any block afterwards — the layout is a starting point, not a lock.
  • Compact shrinks every card to a mini overview that keeps the name and the live value, so a whole model fits on one screen; press it again to restore. The − button on a single card shrinks just that card and the + button expands it again, so you can mix overview and detail freely.
  • Focus — the target button on a card, or Focus this branch in Block settings — opens one block together with everything it is built from, on its own. This is how to work inside a large block with many sub-connections without the rest of the model in the way. Show whole model in the banner, or Esc, leaves the focus view.

Units and dimensional checking

The engine tracks what kind of quantity every number is, and it checks every combination before it computes:

  • Adding and subtracting requires the same kind of quantity — money to money, time to time.
  • Multiplying and dividing combines units: $/unit x units becomes $; units / hrs stays units/hrs.
  • Percentages and plain ratios scale without changing the unit: $5 x 20% is $1.
  • Compatible units convert automatically: 30 min + 1 hr is 90 min. The result shows in the first input's unit, and a Result block can be given a display unit such as hrs to show 1.5 hrs.
  • Incompatible combinations are refused with a plain-language error — money and time cannot be added.

The tool knows these units:

  • $
  • k$
  • M$
  • %
  • x
  • num
  • units
  • users
  • customers
  • hrs
  • min
  • days
  • $/unit
  • units/hrs
  • $/hrs

Any other word you type becomes its own unit. If your domain counts widgets or tickets, type that word and it works the same way — domain-specific models need no configuration.

Reading the result

Values are live everywhere: edit one input and every block and wire updates at once, so you always know the model's current answer and where it came from.

The sensitivity panel ranks inputs by how much they move the result:

  • When an input has a Min and a Max, the engine measures the full min-to-max swing on the result.
  • Otherwise it measures the effect of a +1% change in that input.

Act on the ranking, not on your intuition. Tighten the estimate of the top driver first — if the swing from your biggest uncertainty dominates the ranking, more precision there changes the decision, and precision anywhere else does not. If the top driver is a cost you control, negotiate it. If it is a volume assumption, test it. If two inputs fight for the top spot, the decision is genuinely sensitive to both, and you should plan for both.

Walkthrough: build a monthly profit model from scratch

This builds a complete model using the tool's real interface. On a desktop the Blocks palette is the left panel, listing Value input, Operation, Formula and Result. On a phone the palette opens from the + Blocks button, and the settings panel is called Block settings.

  1. Start clean. Press New in the toolbar. The toolbar also offers Import, Export JSON, Export SVG, Export PNG, Docs and Fit.
  2. Add the four Value inputs. Drag Value input from the Blocks palette onto the canvas four times. Select each one and fill in Block settings with the fields Name, Value, Unit, Min, Likely, Max:
    NameValueUnitMinLikelyMax
    price49$/unit394959
    volume1200units80012001600
    cost per unit18$/unit—18—
    fixed costs9500$—9500—
  3. Wire revenue. Drag from the output port (the round dot on the right of the price block) to an input port (a round dot on the left) of a new Operation block; then wire volume into the second input port. In Block settings set Title to revenue and Operation to Multiply. The block shows 58,800.
  4. Wire variable cost. Add another Operation: cost per unit x volume, Operation = Multiply, Title = variable cost. It shows 21,600.
  5. Wire total cost. Add an Operation with Title total cost, Operation = Add, wired from variable cost and fixed costs. It shows 31,100. Add takes as many inputs as you like — press + add input on the block and a third cost (fees, shipping, royalties) can fold straight into the total instead of chaining another Add block.
  6. Wire profit into the Result. Add an Operation with Title profit, Operation = Subtract, with revenue as a and total cost as b. It shows 27,700. Then add a Result block and wire profit into it. In Block settings the Result has Title and Display unit: set Title to Monthly profit and Display unit to $. The result reads $27,700.
  7. Check the numbers. Every block should now agree:
    BlockCalculationValue
    revenue49 x 1,20058,800
    variable cost18 x 1,20021,600
    total cost21,600 + 9,50031,100
    profit58,800 - 31,10027,700
    Monthly profitResult, display unit $$27,700
  8. Optional: do it in one Formula instead. A single Formula block can replace the four Operation blocks. Add the block, then use Add input in Block settings to create four named inputs on the Inputs list — price, volume, cost, fixed — wire the Value inputs to them, and type the Expression price * volume - (cost * volume + fixed). Wire the Formula straight into the Result. Same answer ($27,700), fewer blocks; the trade-off is that intermediate totals like total cost are no longer visible as their own blocks.
  9. Read the sensitivity panel. Because price and volume have a Min and a Max, the engine measures their full min-to-max swing on the result; the inputs without a range are measured at +1%. Expect price and volume at the top — a swing of 39 to 59 on price alone moves profit by roughly 24,000. If you can only improve one estimate this week, improve the price estimate.
  10. Presentation and export. Set a Display unit on the Result to present the number as you want it. Then use Export SVG for a crisp diagram for a deck or a document, Export PNG for a quick share, and Export JSON to carry the model itself to another device.

Tips and troubleshooting

  • Unconnected ports show an error naming the port. The message points at exactly which input is still empty — wire it and the error clears.
  • Loops are refused. If a wire is rejected, the connection would make values flow in a circle. A model is one-way, from inputs to result.
  • Unit mismatch errors usually mean a labelling mistake. Most often a total was labelled as a per-unit rate (or the reverse) — for example total cost tagged as $/unit. Fix the unit on the offending block.
  • New here, or just exploring? The Blocks palette has ready-made examples — Monthly profit, Line efficiency and Design score. Load one, change the numbers, rewire it; nothing is locked.
  • Formulas resolve names from their own Inputs list. If an expression cannot find a name, that name is missing from the block's Inputs; add it with Add input and wire a value into it.
  • The model autosaves in your browser (localStorage), so closing the tab does not lose your work. Export JSON and Import JSON move a model between devices. Clear data in the toolbar deletes everything this site stored in your browser.
  • Wiring does not need pixel precision. A wire snaps to the nearest legal port and a link dropped on a card uses its first free input — if a connection is refused, the message says why (a loop, a second output, or a unit clash).
  • Big model? Use Arrange, Compact and Focus. Arrange sorts the blocks into flow order, Compact turns them into a one-screen overview, and Focus opens one block with its own inputs.
  • Choose the export for the job. Export SVG stays crisp when zoomed — use it for print and slides — while Export PNG is a 3x raster for places that only accept images.

That is the whole method: assemble one equation from small blocks, wire them together, check the units, and let the sensitivity panel tell you which input deserves your attention. Start with the model you actually need to decide on today.
