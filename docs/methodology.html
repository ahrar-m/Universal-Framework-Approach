Methodology — Universal Framework Approach

Every metric you care about — monthly profit, process efficiency, a product-design score — is a single main equation assembled from small blocks. Blocks plug into one another, wires carry values between them, and any Compute block can be marked as an outcome — a green card carrying the RESULT label. A model can carry several outcomes at once. This page explains how that works and walks you through building a real model from scratch.

Open the tool

The idea

A spreadsheet hides its reasoning inside formulas that are invisible until you click a cell. The Universal Framework Approach makes the reasoning the artefact: a metric is one equation, and the equation is built visually out of small blocks. A Value input holds a named number. A Compute block combines values — either a ready operation or a typed expression over named inputs. Wires carry values from one block to the next. And any Compute block can be marked as an outcome, presenting one of the model's results — mark as many as your model needs.

This beats a spreadsheet for four practical reasons:

  • The shape of the reasoning is visible. You can see the structure of the model at a glance, hand it to a colleague, and argue about the structure rather than about cell references.
  • Every intermediate value is exposed. Revenue, variable cost and total cost are real blocks with real numbers on them — not side calculations in columns F through K.
  • Units are checked. The engine knows what kind of quantity each number is, so a total mistakenly used as a per-unit rate is caught instead of quietly producing nonsense.
  • You can see which input actually drives the outcome. The sensitivity panel ranks your inputs by how much they move each outcome.

The two block types

Value input

A named number with a unit

A Value input is a named number with a unit and an optional Min / Likely / Max range. It is named because expressions refer to inputs by name, not by position.

Example: price — value 49, unit $/unit, min 39, likely 49, max 59.

Compute · ready operation

Two ports or twenty, one calculation

One block does all the combining: Compute. When you add it the dialog asks How should it compute?, and one of its two faces is a ready operation: Add, Subtract, Multiply, Divide, Power, Minimum, Maximum, Round, Percent of, with the result shown directly on the block. Subtract, Divide, Power, Round and Percent of have two input ports, a and b. Add, Multiply, Minimum and Maximum take as many inputs as you like: press + add input on the block (or Add input in Block settings) to grow the list, and every input is folded into the one result. Empty ports are ignored, a single connected input passes straight through, and every term is checked to be the same kind of quantity.

Example: a Multiply Compute block with a = price (49) and b = volume (1,200) shows 58,800.

Compute · typed expression

The same block, typed out

The other face of Compute holds one typed expression over named inputs, for example price * volume * (1 - churn). The block's inputs are the named ports you add to it — anything the expression references must be one of those inputs. The expression goes through a safe parser built for this job, never code: it knows min max round floor ceil abs sqrt pow exp ln log and sign. Switch a Compute block between its two faces at any time in Block settings (How it computes) — wires survive wherever the ports do.

Example: a Compute block with inputs price, volume and churn can use those three names and nothing else.

Marked outcome

Any Compute block can be a result

A result is not a block of its own. Any Compute block can be marked as an outcome with the Mark as a result button in Block settings. Marking gives the card green RESULT styling, an optional Display unit that presents the number the way you want, a place in the Results and what moves them panel, and its own sensitivity ranking. Marking never changes the wiring: the block still computes and still feeds any wires that leave it, so the same block can be both an outcome and an intermediate step. Mark as many as you need — an initial investment and a monthly profit side by side, for example.

Example: the profit Compute block (Subtract), marked as a result, Display unit $, showing $27,700.

How values flow

Wires connect an output port to an input port. The model is a directed acyclic graph: values travel one way, from the inputs onwards to the outcomes you mark. There is no back-flow and no hidden state.

  • Loops are refused. If wiring a connection would create a cycle, the tool rejects it. A model is a computation, not a feedback simulation.
  • Each block shows its current value. Change an input and every downstream block updates immediately.
  • Each wire shows what it carries. You can follow a number from the input that produced it, through every intermediate step, to the outcome it feeds.

Wiring without the fiddling

Connecting two blocks should not take three attempts. Four shortcuts make a link hard to miss, plus one that undoes one:

  • Wires magnetise to ports. Drag from a port towards the next block — well before you reach it, the wire snaps to the nearest port it is allowed to reach and lights it up. Release anywhere in that area and the link is made.
  • Drop the wire on the card itself. Let go anywhere on a block and the wire lands on that block's first free input — or on its output when you drag from an input. On an Add or Multiply block whose inputs are all filled, a fresh input is grown for the wire.
  • Tap, then tap. On touch: tap the output port, then tap the destination card or its port. While you decide, every port that can accept the link glows; tapping the same port again abandons the link.
  • Add the next block already wired. Press and hold a port on a phone — or right-click it with a mouse — and a menu offers exactly the blocks that fit there: Add Value input here or Add Compute here to feed an input port, and Add Compute here to consume an output. The new block is named in a small dialog, lands on the side the value flows from, and is connected before it appears. The same menu offers Start a wire from here and, on a connected port, Disconnect.
  • Removing a wire. Tap the wire — it lights up and a small bar names the link — then tap Delete wire. This is the phone-friendly path, where there is no Delete key to press. You can also open the destination block's settings and tap the × beside the input to drop just that wire, or press Delete on a keyboard.

Keeping large models readable

  • Arrange glides the blocks into flow order: every value input lands beside the block it is wired into (lined up with the port it feeds, instead of a far-left column), outcomes on the right, and columns ordered so wires stay short and crossings few. Unrelated branches get their own horizontal bands, so wires from one part of the model never weave through another. You can still drag any block afterwards — the layout is a starting point, not a lock.
  • Compact shrinks every card to a mini overview that keeps the name and the live value, so a whole model fits on one screen; press it again to restore. The − button on a single card shrinks just that card and the + button expands it again, so you can mix overview and detail freely.
  • Focus — the target button on a card, or Focus this branch in Block settings — opens one block together with everything it is built from, on its own. This is how to work inside a large block with many sub-connections without the rest of the model in the way. Show whole model in the banner, or Esc, leaves the focus view. Entering and leaving Focus never moves the camera — on a big graph the zoom jump costs more than it helps — so the view stays exactly where you put it. Prefer the old behaviour? Switch on Auto-fit camera in the View menu at the bottom left of the canvas and Focus re-frames the branch again.

Units and dimensional checking

The engine tracks what kind of quantity every number is, and it checks every combination before it computes:

  • Adding and subtracting requires the same kind of quantity — money to money, time to time.
  • Multiplying and dividing combines units, and labels cancel along the way: $/unit x units becomes $, ₹/tower x tower becomes ₹, and units / hrs stays units/hrs.
  • Percentages and plain ratios scale without changing the unit: $5 x 20% is $1.
  • Compatible units convert automatically: 30 min + 1 hr is 90 min. The result shows in the first input's unit, and a marked outcome can be given a display unit such as hrs to show 1.5 hrs.
  • Incompatible combinations are refused with a plain-language error — money and time cannot be added.

The tool knows these units:

  • $
  • k$
  • M$
  • %
  • x
  • num
  • units
  • users
  • customers
  • hrs
  • min
  • days
  • $/unit
  • units/hrs
  • $/hrs

Any other word you type becomes its own unit. If your domain counts widgets or tickets, type that word and it works the same way — domain-specific models need no configuration. The unit box stays out of your way: it only suggests the units this model already uses, never a stock list.

Reading the result

Values are live everywhere: edit one input and every block and wire updates at once, so you always know the model's current answer and where it came from.

The Results and what moves them panel shows every marked outcome and, for each one, ranks how much its inputs move it:

  • When an input has a Min and a Max, the engine measures the full min-to-max swing on the outcome.
  • Otherwise it measures the effect of a +1% change in that input.

Each marked outcome gets its own ranking, so a model with an initial investment and a monthly profit side by side tells you what moves each of them. Act on the ranking, not on your intuition. Tighten the estimate of the top driver first — if the swing from your biggest uncertainty dominates the ranking, more precision there changes the decision, and precision anywhere else does not. If the top driver is a cost you control, negotiate it. If it is a volume assumption, test it. If two inputs fight for the top spot, the decision is genuinely sensitive to both, and you should plan for both.

Walkthrough: build a monthly profit model from scratch

This builds a complete model using the tool's real interface. On a desktop the Blocks palette is the left panel, listing Value input and Compute. On a phone the palette opens from the + Blocks button, and the settings panel is called Block settings.

  1. Start clean. Press the Settings gear at the top right and choose New. Behind that gear are all the model actions: Import, Export JSON, Export SVG, Export PNG and Clear data; the toolbar keeps Docs. The canvas view controls sit at the bottom left: − and +, plus a View button that pops out 1:1, Fit, Arrange, Compact and Auto-fit camera.
  2. Add the four Value inputs. Add Value input from the Blocks palette four times — each one opens a small dialog that takes the Name, Unit and Value right away (press Enter to add it). Select each card afterwards to complete Block settings with Min, Likely and Max:
    NameValueUnitMinLikelyMax
    price49$/unit394959
    volume1200units80012001600
    cost per unit18$/unit—18—
    fixed costs9500$—9500—
  3. Wire revenue. Drag from the output port (the round dot on the right of the price block) to an input port (a round dot on the left) of a new Compute block; then wire volume into the second input port. The add dialog asks How should it compute? — choose Ready operation and set Operation to Multiply. In Block settings set Title to revenue. The block shows 58,800.
  4. Wire variable cost. Add another Compute: cost per unit x volume, Operation = Multiply, Title = variable cost. It shows 21,600.
  5. Wire total cost. Add a Compute block with Title total cost, Operation = Add, wired from variable cost and fixed costs. It shows 31,100. Add takes as many inputs as you like — press + add input on the block and a third cost (fees, shipping, royalties) can fold straight into the total instead of chaining another Add block.
  6. Wire profit, then mark it as the outcome. Add a Compute block with Title profit, Operation = Subtract, with revenue as a and total cost as b. It shows 27,700. Then press Mark as a result in Block settings: the card turns green and takes the RESULT label, and the number appears in the Results and what moves them panel. Set Display unit to $ and the outcome reads $27,700. Marking never changes the wiring — profit still feeds anything wired from it — and you can mark as many Compute blocks as you need, each its own outcome.
  7. Check the numbers. Every block should now agree:
    BlockCalculationValue
    revenue49 x 1,20058,800
    variable cost18 x 1,20021,600
    total cost21,600 + 9,50031,100
    profit58,800 - 31,10027,700
    profit, markedSubtract, marked as a result, display unit $$27,700
  8. Optional: do it in one Compute block instead. The same block has a second face: a typed expression over named inputs. Add the block and choose Typed expression under How should it compute? — or flip any Compute block between its two faces with How it computes in Block settings, where wires survive wherever the ports do. Type the Expression price * volume - (cost * volume + fixed): the names it uses become the block's Inputs — price, volume, cost, fixed — which you can rename or extend with Add input. Wire the four Value inputs into those ports and press Mark as a result. Same answer ($27,700), fewer blocks; the trade-off is that intermediate totals like total cost are no longer visible as their own blocks.
  9. Read the sensitivity panel. Each marked outcome gets its own ranking. Because price and volume have a Min and a Max, the engine measures their full min-to-max swing on the outcome; the inputs without a range are measured at +1%. Expect price and volume at the top — a swing of 39 to 59 on price alone moves profit by roughly 24,000. If you can only improve one estimate this week, improve the price estimate.
  10. Presentation and export. Set a Display unit on the marked outcome to present the number as you want it. Then use Export SVG for a crisp diagram for a deck or a document, Export PNG for a quick share, and Export JSON to carry the model itself to another device.

Tips and troubleshooting

  • Unconnected ports show an error naming the port. The message points at exactly which input is still empty — wire it and the error clears.
  • Loops are refused. If a wire is rejected, the connection would make values flow in a circle. A model is one-way, from inputs onwards.
  • Unit mismatch errors usually mean a labelling mistake. Most often a total was labelled as a per-unit rate (or the reverse) — for example total cost tagged as $/unit. Fix the unit on the offending block.
  • Not seeing a result? The Results and what moves them panel only lists marked outcomes. Select a Compute block and press Mark as a result in Block settings — or check the Model check panel, which says so plainly.
  • Typed expressions resolve names from their own Inputs list. If an expression cannot find a name, that name is missing from the block's Inputs; add it with Add input and wire a value into it.
  • Model files are version 2. Exports and browser saves made by older versions of the tool are not migrated — the app starts with a fresh model and says so. Export from the old version first if you still need it.
  • The model autosaves in your browser (localStorage), so closing the tab does not lose your work. Export JSON and Import JSON move a model between devices. Clear data in the Settings menu at the top right deletes everything this site stored in your browser.
  • Wiring does not need pixel precision. A wire snaps to the nearest legal port and a link dropped on a card uses its first free input — if a connection is refused, the message says why (a loop, a second output, or a unit clash).
  • Big model? Use Arrange, Compact and Focus. Arrange sorts the blocks into flow order, Compact turns them into a one-screen overview, and Focus opens one block with its own inputs. All three sit in the View menu at the bottom left of the canvas — and leave Auto-fit camera off to keep the view still while you move in and out of Focus.
  • Choose the export for the job. Export SVG stays crisp when zoomed — use it for print and slides — while Export PNG is a 3x raster for places that only accept images. Every exported file is named after the model plus a date-timestamp (like monthly-profit-20250929-142530.svg), so exporting twice never overwrites the earlier file.

That is the whole method: assemble one equation from small blocks, wire them together, check the units, mark the outcome you care about, and let the sensitivity panel tell you which input deserves your attention. Start with the model you actually need to decide on today.
